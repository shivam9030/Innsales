*   **Authentication**: JWT (JSON Web Tokens) stored in LocalStorage for persistent sessions.

## 3. CORE ARCHITECTURE & DESIGN PATTERNS

### A. The "Provider" Pattern (Context API)
We have two global providers wrapping the app in `App.jsx`:
1.  **AuthProvider**: Manages `user`, `isAuthenticated`, and `loading` status.
2.  **CartProvider**: Manages `cartItems`, `cartCount`, and total calculations.
*   **Why?**: This prevents "Prop Drilling" (passing data through 5 layers of components) and ensures the UI stays consistent (e.g., Navbar count matches the Basket).

### B. The "Service" Pattern
All API logic is separated into `src/services/` (e.g., `authService.js`, `basketService.js`).
*   **Why?**: It keeps components "Lean." Components only care about the *data*, not the *URL* or the *HTTP method*.

### C. The "HOC" & Hook Pattern
We use `React.memo` (HOC) and hooks like `useCallback` to optimize the component lifecycle.

## 4. THE OPTIMIZATION MASTERCLASS (The Interview "Winner")

### I. Rendering Optimization (`React.memo`)
*   **Implementation**: Applied to `Navbar`, `ProductPage`, `BasketPage`.
*   **Effect**: Prevents a component from re-rendering if its parent changes but its own props stay the same.

### II. Referential Stability (`useCallback`)
*   **Implementation**: Used for all event handlers (e.g., `handleAddToCart`) passed to children.
*   **Effect**: Prevents unnecessary re-renders of memoized child components by keeping function references stable.

### III. Calculation Memoization (`useMemo`)
*   **Implementation**: Used for calculating `cartCount`, `subtotal`, and `tax` in the basket.
*   **Effect**: Prevents expensive array operations (like `.reduce`) from running on every render unless the `cartItems` array itself changes.

## 5. USER WORKFLOW & LOGIC

1.  **Initialization**: `App.jsx` loads -> `AuthContext` checks LocalStorage for a token -> If valid, user is logged in.
2.  **Browsing**: User visits `DashboardPage` -> Categories are fetched -> Clicking a category fetches products.
3.  **Shopping**: User clicks "Add to Cart" -> `CartContext.addItem()` is called -> API is hit -> Global state is updated -> Navbar count updates instantly.
4.  **Checkout**: User visits `BasketPage` -> Subtotals are calculated via `useMemo` -> User proceeds to `CheckoutPage` -> `StripePaymentPage` handles secure payment logic.

---

## 6. ERROR HANDLING & USER EXPERIENCE (UX)
*   **Loading States**: Custom spinners and loading flags in `AuthContext` prevent "flicker" on page refresh.
*   **Toasts/Notifications**: Used in `Dashboard` and `ProductPage` to give instant feedback when an item is added.
*   **Safe Navigation**: Unauthorized users are automatically redirected to `/login` via the `AppRoutes` logic.

## 7. GLOSSARY OF TERMS (Be ready to define these!)
*   **Prop Drilling**: Passing data through multiple layers of components that don't need it. (We avoided this using Context).
*   **Memoization**: An optimization technique where you store the results of expensive function calls and return the cached result when the same inputs occur again.
*   **JWT (JSON Web Token)**: A secure way to transmit information between the client and server as a JSON object. Used for our authentication.
*   **Side Effect**: Any code that interacts with the outside world (like an API call). We handle these inside `useEffect`.
*   **Immutability**: The practice of never changing data directly (e.g., using `[...items, newItem]` instead of `items.push(newItem)`).
